## YueYue Launcher vs Xenon

Xenon 是一个基于 HMCL 开发的 Mindustry 启动器，项目本身继承了 HMCL 的设计思路和 Java 技术路线。

YueYue Launcher 则选择了 **Tauri + Rust**，重点放在轻量化和较低的运行开销上。

两者并不是简单的替代关系，而是不同的设计取向。

| 对比项           | YueYue Launcher  | Xenon                 |
| ------------- | ---------------- | --------------------- |
| 定位            | 轻量 Mindustry 启动器 | HMCL 风格 Mindustry 启动器 |
| 技术路线          | Tauri + Rust     | Java 17 / HMCL        |
| 界面            | 独立 GUI           | HMCL 风格 GUI           |
| 安装包           | ≈ 2 MB           | jar 13 MB        |
| 核心程序          | ≈ 5 MB           | exe 59 MB        |
| Windows 启动后内存 | ≈ 4–5 MB*        | ≈ 160 -300? MB**            |
| Windows EXE   | 约 5 MB 核心程序*     | 实测 EXE 约 59 MB**      |
| 多实例           | 支持               | 支持                    |
| 版本管理          | 支持               | 支持                    |
| Mod 管理        | 不支持               | 支持                    |
| 下载管理          | 支持               | 支持                    |
| 跨平台           | Windows / Linux  | 取决于 Xenon 当前版本        |

* YueYue Launcher 数据来自当前开发版本测试。

** Xenon 数据为 Windows 环境下的个人实测结果，不代表所有电脑和所有版本的实际表现。

### Windows 资源占用实测

在相同 Windows 使用场景下，对 Xenon 进行了实际观察：

* 启动后内存约 **160 MB 随后可能增加到近300 MB**
* EXE 文件约 **59 MB**
* 点击不同功能按钮后，内存会产生明显波动
* 连续进行较多操作时，内存曾达到约 **300-500 MB**
* 后续经过系统/程序清理后会下降
* 再次进行操作时，内存占用可能再次上升

因此这里不把 **160 MB 或 500 MB** 当成 Xenon 的“固定内存占用”，而是将其视为实际使用过程中的观察值。

YueYue Launcher 当前测试结果约为 **4–5 MB**，因此两者在资源占用方面存在比较明显的差异。

## YueYue Launcher 的优势

### 1. 更轻量

这是 YueYue Launcher 最明确的目标。

安装包约 **2 MB**，核心程序约 **5 MB**，运行时目前约 **4–5 MB**。

对于只需要启动和管理 Mindustry 的用户来说，不需要为启动器本身准备大量额外资源。

### 2. 启动器自身占用较低

YueYue Launcher 使用 Tauri + Rust，而不是完整的 Java 启动器运行环境。

因此可以在保持 GUI 的情况下，将启动器本身的运行开销控制在较低水平。

### 3. 更专注 Mindustry

YueYue Launcher 不需要兼容 mod 或 server 等其他场景。

功能主要围绕：

* Mindustry 实例
* 游戏版本
* Mod
* 下载
* 启动参数
* 游戏管理

进行设计。

### 4. 更适合长期常驻

如果用户经常打开启动器、管理多个实例或者频繁切换版本，较低的启动器资源占用可以减少后台常驻带来的负担。

### 5. 结构相对简单

Tauri + Rust 的架构让核心功能可以保持较小，同时前端仍然可以使用 Vue 进行 UI 开发。

这也是 YueYue Launcher 能够保持较小体积的重要原因之一。

## Xenon 的优势

YueYue Launcher 并不是全面优于 Xenon。

Xenon 最大的优势之一，就是它建立在 **HMCL 的成熟基础上**。Xenon 仓库本身也明确说明它是 HMCL 的 fork。

### 1. HMCL 生态基础

HMCL 本身是一个经过长期发展的开源启动器，拥有大量成熟的启动器设计经验和代码基础。

因此 Xenon 可以利用这套成熟体系，而不是从零开始设计所有启动器功能。

### 2. 功能体系更加成熟

Xenon 的设计并不只是“打开 Mindustry”。

它更接近一个完整的游戏启动器，因此在界面、设置、版本管理等方面具有较完整的启动器体验。

### 3. UI 体系成熟

对于使用过 HMCL 的用户来说，Xenon 的交互方式比较容易理解。

熟悉 HMCL 的用户基本不需要重新学习一套完全不同的启动器逻辑。

### 4. 项目积累更多

Xenon 背后使用的是已经经过长期验证的 HMCL 技术路线。

相比之下，YueYue Launcher 是一个更年轻的项目。

### 5. 更适合喜欢完整启动器体验的用户

如果你更重视：

* 功能完整度
* 成熟的 UI
* HMCL 风格
* 已有启动器使用习惯

那么 Xenon 仍然是一个很合理的选择。

---

## YueYue Launcher 的不足

我们也不隐藏自己的问题。

### 1. 项目还比较年轻

Xenon 有 HMCL 作为基础，而 YueYue Launcher 很多功能需要自己逐步完善。

### 2. 生态较小

目前没有 Xenon 那样成熟的用户基础和社区生态。

### 3. 功能仍在增加

部分高级功能还没有完全完成。

目前更强调核心功能和轻量化，而不是一次性加入大量功能。

### 4. 跨平台仍需要继续完善

虽然技术路线支持跨平台，但不同系统仍然需要实际测试和持续适配。

### 5. UI 还没有达到成熟启动器的完成度

YueYue Launcher 更强调功能和轻量化，目前 UI 仍处于持续设计和优化阶段。

---

## 两个项目怎么选？

### 选择 YueYue Launcher

如果你更在意：

* 小体积
* 低内存
* 快速启动
* 简洁界面
* Mindustry 专用
* 低配置电脑

那么可以尝试 YueYue Launcher。

### 选择 Xenon

如果你更在意：

* HMCL 风格
* 更成熟的启动器体验
* 完整的功能体系
* 已经习惯 HMCL 的操作方式

那么 Xenon 可能更适合你。

---

## 最后

我们并不认为：

> **“内存占用低 = 一定比 Xenon 好。”**

启动器的体验不仅仅取决于内存。

Xenon 的优势在于成熟的 HMCL 基础和完整的启动器体验；YueYue Launcher 的优势则是**轻量、简单和专注 Mindustry**。

两者选择的是不同方向。

> **Xenon：在成熟的 HMCL 基础上做好 Mindustry。**
> **YueYue Launcher：尽可能用更少的资源做好 Mindustry。**
